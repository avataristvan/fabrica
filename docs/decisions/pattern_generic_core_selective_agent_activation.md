Rule: ai-mem's own source must stay agent-agnostic. Per-agent behavior is opt-in and lives in the USER's own config (`~/.config/ai-mem/agents.yaml`'s `inject_agents`/`signatures`), never as a hardcoded agent name in ai-mem's source. Selectivity happens at RUNTIME inside `agent_context.py` (`should_inject`, checked against the allowlist) -- there is exactly one generic hook registration per event in `settings.json`, never a separate registration per agent. Whatever `install.py` DOES write to disk (hook entries, MCP registration, permissions, installed slash-commands) must have a matching cleanup path in `uninstall.py`, and `install.py` itself must self-heal stale entries from a prior version on re-run (see `_remove_hook_command`/`_upsert_hook_command`) -- this is what 'ai-mem stays installable/updatable' means operationally. `~/.config/ai-mem/agents.yaml` and `~/.local/share/ai-mem/` (the memory DB) are the deliberate exception: user config/data that neither `install.py` creates nor `uninstall.py` removes, same as any other user data.
When: Adding any new agent-aware feature to ai-mem, or writing documentation (CLAUDE.md, memory) that describes it. Also the checklist to run before documenting any hook/routing change: (1) does ai-mem's own source name a specific agent? should not. (2) is per-agent activation opt-in via the user's own config? should be. (3) does install.py write anything that isn't mirrored in uninstall.py's cleanup, or that isn't self-healed by install.py itself on re-run?
Why: Validated 2026-09-13 against the actual code while reviewing the PreToolUse retirement (arch_decision_pretool_push_removed_2026_09_12) for CLAUDE.md documentation -- all three properties already held (confirmed, not assumed): `_BUILTIN_INJECT_AGENTS = frozenset({"general-purpose"})` contains only a true Claude Code built-in; `the-coder` exists only in the user's own agents.yaml, never in ai-mem's source; `uninstall.py`'s own docstring explicitly excludes `~/.config/ai-mem/` and `~/.local/share/ai-mem/` from cleanup by design. This is also why the three-tier pull design for the-coder/chunk-plan (design_three_tier_pull_the_coder_2026_09_12) belongs entirely in ai-mem's own memory and in those external files themselves -- never in ai-mem's own CLAUDE.md, since the-coder is a consumer of ai-mem's API, not part of the installable ai-mem package.
