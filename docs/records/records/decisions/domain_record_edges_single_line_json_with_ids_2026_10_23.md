---

Decision: Record edges are stored as single-line JSON in the frontmatter (`edges: [{"target_id": ..., "edge_type": ...}]`), with ids as targets, not paths.
Why: Continuity with the former Chroma `edges` metadata field (a JSON string). The line-based `key: value` frontmatter parser then needs no YAML library; multi-line YAML was explicitly rejected in docs/sources/adr-migration-chunk-plan.md (Chunk 1, step 3). Ids stay stable when a type change (learnings/ <-> decisions/) or `mem move` relocates a file; paths would break. Note: no record states a YAML prohibition as such. Stdlib-only (`dependencies = []`) is documented as current state (docs/reference/architecture.md, cli.md), with the general rationale in [domain_drop_mcp_server_for_cli_plugin_2026_10_10](../../architecture/decisions/domain_drop_mcp_server_for_cli_plugin_2026_10_10.md); the YAML choice was a parsing-simplicity argument.
Scope: docs/reference/record-format.md, `edges` field. Clickable Markdown links, if wanted later, are derived (e.g. generated by mem-adr-sync into a body section or INDEX.md), never the source of truth. Open option, discussed and not decided: a more compact single-line edge syntax (e.g. `edges: derived_from learning_x, related ../ai-architecture:pattern_y`).
Evidence: docs/sources/adr-migration-chunk-plan.md (Chunk 1, steps 3-4), docs/reference/record-format.md (edges row), librarian answer 2026-10-23.
