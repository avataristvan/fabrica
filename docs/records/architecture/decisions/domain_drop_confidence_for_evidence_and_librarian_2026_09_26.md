Decision: ai-mem drops confidence and access_count as a trust signal. In their place come traceable evidence: an edge 'confirms' (new) from a later record to the earlier one it confirms, plus the existing edges 'supersedes' and 'contradicts'. Retrieval is taken over by a librarian (todo_bibliothekar_haiku_retrieval_agent_2026_09_25): a cheap agent that reads INDEX.md, records and edges and judges while reading, instead of sorting by a number. The librarian is an approach on probation, not an established solution.

Why: The number converges to popularity, not to relevance. Frequently retrieved entries rise regardless of whether they fit the question (observed 2026-05-18, todo_retrieval_confidence_gradient); even maintenance accesses via mem_get increased access_count (todo_dream_maintenance_batch_2026_09_25). Above all, the number conceals its why: '0.8' mixes boosts, retrievals and real confirmation, and a reader cannot reconstruct from it why they should trust the entry. An edge 'confirms', by contrast, shows where and by what a finding was confirmed. A reader can check it and weigh it, instead of believing a number. This is domain_direction_judgment_over_scores_2026_09_20 carried through to its conclusion. Side effects: the conflict between frequently mutating confidence and rarely changing ADR files disappears, and the framework becomes transferable to systems without a score field (Confluence, Langdock), where records and references work the same way. The removal is low-risk: since the ML ranker was removed (2026-06), confidence no longer influenced hit order; it only controlled the [available] block (only with session_start_verbose) and the promotion list in mem-dream.

Test standard for the librarian: the ML ranker and the ADSR idea (todo_confidence_decay_adsr_design) first had to show their strengths and weaknesses in use over months; the same applies to the librarian. Measurable against the existing gap-test cases (scripts/eval_pull/). Known open question: it improves WHAT is found, not THAT anyone asks (pattern_triggers_beat_storage_and_ranking). It needs fixed call points (e.g. /chunk-plan, before architecture decisions), otherwise it stays unused.

Scope: Applies to all collections and to the framework in general. Supersedes pattern_confidence_lifecycle. Implementation in this order: (1) librarian prototype plus measurement against scripts/eval_pull/; (2) remove confidence/access_count from the [available] gate, the mem-dream confidence report and tracking, reduce mem_boost to setting the cue (the cue of the experience index currently hangs on mem_boost and must be kept), introduce the edge type 'confirms' in mem_link, adapt the framework text (then docs/epistemology-framework.md, now the source docs/sources/epistemology_framework.md; layer 3 is then /reflect + records + evidence edges + librarian, no longer the confidence lifecycle). Technically the removal does not depend on the librarian, but it follows it so that it becomes visible whether the librarian lacks a trust signal. The ADSR idea is thereby moot: active downgrading on error is done by supersedes/contradicts; passive fading over time is rejected because 'old' does not mean 'wrong' (domain_superseded_flag_not_hide_2026_09_20).

Implemented: Both steps are complete. (1) Librarian prototype: da3f2ab (examples/agents/librarian.md, Haiku, read-only), measured in eval_librarian_2026_09_26 against scripts/eval_pull/ (5/6 gap cases solved, versus 2/6 with plain cosine/hybrid retrieval). (2) Removal: b5e5d38 (mem_boost reduced to boost_count+cue, EdgeType extended by 'confirms', [available] gate on boost_count ≥ 1, AddMemoryUseCase/TrackAccessUseCase/BoostConfidenceUseCase no longer read/write confidence/access_count, mem-dream confidence report removed). Fixed call points for the librarian followed in 39a44e7 (mandatory call in /chunk-plan, reference in the workspace CLAUDE.md; registered as subagent type librarian via symlink ~/.claude/agents/librarian.md). The librarian nevertheless remains an approach on probation (see eval_librarian_2026_09_26: general-purpose instead of the registered type was measured, the tools: restriction was not actually enforced — re-test with the registered type took place 2026-09-29, see eval_librarian_rerun_records_layout_2026_09_29; todo_bibliothekar_haiku_retrieval_agent_2026_09_25).
