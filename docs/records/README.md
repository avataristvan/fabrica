# Records

This directory holds repo-scoped knowledge from ai-mem's `repo.ai-mem` collection,
persisted as git-native Markdown files — one file per entry, generated by
`mem-adr-sync export` (never hand-written; edit the underlying ai-mem entry and
re-export instead of editing a file here directly). Records are not limited to
software architecture; any area (marketing, pricing, ops, ...) fits.

- **Layout:** `<area>/<kind>/<id>.md`. `<kind>` is `decisions/` for
  `domain`/`pattern`/`anti-pattern` entries and `learnings/` for `learning`
  entries (observed facts). `<area>` defaults to `general`.
- **Filename = ai-mem entry ID** (e.g. `domain_bmad_vs_ai_mem_epistemology_2026_09_25.md`).
- **Learning -> decision:** a decision based on a learning carries a
  `derived_from` edge pointing at it.
- **Frontmatter schema:** see `docs/reference/record-format.md` for the full field list,
  fixed field order, and which fields (confidence, access_count, boost_count,
  last_accessed_at, cue) are deliberately never persisted here.
- **Superseded, not deleted:** when a record is replaced, the old entry gets
  a `superseded_by: <id>` frontmatter field instead of being removed — the
  file stays as a historical record.
- **`INDEX.md`** is the entry point for browsing: a compact
  `id | area | type | title | status` table covering every record. Read it first
  instead of grepping across every file. Regenerated by `mem-adr-sync reindex`
  or as the final step of `mem-adr-sync export`.

To rebuild ChromaDB from these files (e.g. after a fresh clone), run
`mem-adr-sync import --collection repo.ai-mem`.
